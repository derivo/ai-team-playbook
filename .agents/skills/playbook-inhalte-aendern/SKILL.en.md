# Update and adapt playbook content

[Deutsch (Standard)](SKILL.md) | English

The German `SKILL.md` is the executable, authoritative skill entry point.

Read [Documentation structure and maintenance](../../../docs/README.en.md), the
affected document, and its request. If the adaptation goal is missing, ask for
the context; do not invent team policy. Check existing variants before adding one.

Treat the German default and English `.en.md` file as one language pair. Update
both in the same change and verify that status, claims, links, and change history
match substantively. If an older document lacks one version, create it to the
same scope as the existing content.

Distinguish an update to the shared proposal from an explicitly requested team
variant. Create a variant only on request; link it to its source and document the
differences; a variant for a named context is a use case under
`docs/anwendungsfaelle/`. New variants follow the [content template](../../../docs/vorlagen/inhalt.en.md).

Check changed sources and claims that remain in the affected document. Change
only the requested parts. Keep general processes and use cases separate:
context-specific content belongs in the use case.

Evaluate status from evidence: editing does not make a draft proven. When
superseding content, name the reason and successor or state that none exists.
Update maintenance metadata and change history, linking the local request or real
issue/PR. Do not present a change date as practical evidence.

Check links, format, language pairing, and claims under the shared standard. For
skills or project rules, preserve a rollback path and conduct an adversarial
review. Report results and open points; do not infer permission to commit or
publish.
